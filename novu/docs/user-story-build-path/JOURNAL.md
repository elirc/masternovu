# User Story Build Path Journal

## Inspection Refresh: Future Story Bank

The current 10 tickets stay on contexts so the build path escalates cleanly, but the workflow list is a strong future story bank once those tickets are complete. The real workflow path starts at `WorkflowsPage`, where query, tags, status, sort, offset, and limit become fetch inputs (`apps/dashboard/src/pages/workflows.tsx:83-213`). It renders `WorkflowList`, which owns table sorting and pagination behavior (`apps/dashboard/src/components/workflow-list.tsx:71-194`), and `WorkflowRow`, which owns row actions like edit, trigger, delete, pause, duplicate, sync, and translations (`apps/dashboard/src/components/workflow-row.tsx:125-239`). The backend list endpoint is `WorkflowController.searchWorkflows`, which requires workflow read permission and creates a `ListWorkflowsCommand` from query params and user session (`apps/api/src/app/workflows-v2/workflow.controller.ts:260-285`). The repository stores workflows as notification templates and supports search, tags, status, sort, skip, and limit (`libs/dal/src/repositories/notification-template/notification-template.repository.ts:344-399`). Good follow-on stories after Story 10 would add workflow-list columns, stronger filtering, or dashboard e2e coverage around pause/delete flows.

## Story Design Rationale

The stories are grounded in the contexts feature because it is real product surface and crosses the dashboard, API, shared types, and DAL without requiring the entire notification delivery engine on the first tickets. The path is visible from route constants (`apps/dashboard/src/utils/routes.ts:68-70`) to dashboard route registration (`apps/dashboard/src/main.tsx:286-309`), page composition (`apps/dashboard/src/pages/contexts.tsx:10-35`), table behavior (`apps/dashboard/src/components/contexts/context-list.tsx:140-281`), row actions (`apps/dashboard/src/components/contexts/context-row.tsx:49-164`), API calls (`apps/dashboard/src/api/contexts.ts:10-142`), backend controller endpoints (`apps/api/src/app/contexts/contexts.controller.ts:39-205`), use cases (`apps/api/src/app/contexts/usecases/list-contexts/list-contexts.usecase.ts:11-90`), shared context types (`packages/shared/src/types/context.ts:4-82`), and Mongo schema/indexes (`libs/dal/src/repositories/context/context.schema.ts:5-69`).

## Difficulty Progression

Stories 1-3 stay mostly in existing UI copy and examples so you can practice editing without crossing contracts. Stories 4-5 add data display and URL-state filtering using existing API support (`apps/dashboard/src/components/contexts/hooks/use-contexts-url-state.ts:10-19`, `apps/dashboard/src/api/contexts.ts:57-59`, `apps/api/src/app/contexts/usecases/list-contexts/list-contexts.usecase.ts:21-23`). Stories 6-7 introduce a new API path and dashboard lookup flow while reusing existing get-by-type/id behavior (`apps/dashboard/src/api/contexts.ts:76-90`, `apps/api/src/app/contexts/contexts.controller.ts:152-178`). Stories 8-9 require full-stack schema, DTO, mapper, UI, and tests. Story 10 adds caching/performance implications around search suggestions, building on the current regex search and key indexes (`apps/api/src/app/contexts/usecases/list-contexts/list-contexts.usecase.ts:29-32`, `libs/dal/src/repositories/context/context.schema.ts:50-65`).

## What A Tech Lead Would Watch

A tech lead would watch for contract drift between generated dashboard DTO imports and backend DTO changes (`apps/dashboard/src/api/contexts.ts:1-6`, `apps/api/package.json:30-32`), permission mismatches between frontend routes and backend endpoints (`apps/dashboard/src/main.tsx:286-309`, `apps/api/src/app/contexts/contexts.controller.ts:54-204`), missing environment/organization scoping in queries (`apps/api/src/app/contexts/usecases/list-contexts/list-contexts.usecase.ts:16-19`), and performance regressions from per-row database lookups or unindexed search (`libs/dal/src/repositories/context/context.schema.ts:38-65`). The stories intentionally ask for acceptance criteria and failure modes so every ticket trains review instincts, not just implementation speed.
