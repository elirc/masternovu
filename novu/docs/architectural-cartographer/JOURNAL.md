## Inspection Refresh: Workflow Surface

This pass also verified the heavier workflow surface because it is the product's main notification-design lane. The dashboard route table sends environment-scoped workflow traffic to `WorkflowsPage` behind `PermissionsEnum.WORKFLOW_READ`, with nested create, template, and duplicate drawer routes behind write permissions (`apps/dashboard/src/main.tsx:183-219`). `WorkflowsPage` owns search/tag/status URL state, debounces text search, fetches workflow data, and renders `WorkflowList` (`apps/dashboard/src/pages/workflows.tsx:83-213`, `apps/dashboard/src/pages/workflows.tsx:512-531`). The data hook uses React Query with an environment-aware query key and `getWorkflows` as the fetcher (`apps/dashboard/src/hooks/use-fetch-workflows.ts:17-39`), while the HTTP wrapper injects bearer auth, JSON headers, and `Novu-Environment-Id` before calling `/v2` endpoints (`apps/dashboard/src/api/api.client.ts:40-65`, `apps/dashboard/src/api/api.client.ts:103-112`). On the backend, `WorkflowController` is mounted at `/v2/workflows`, requires authentication, and maps list requests to `ListWorkflowsCommand` (`apps/api/src/app/workflows-v2/workflow.controller.ts:100-120`, `apps/api/src/app/workflows-v2/workflow.controller.ts:260-285`). `ListWorkflowsUseCase` delegates to `NotificationTemplateRepository.getList`, then maps notification templates into minified workflow DTOs (`apps/api/src/app/workflows-v2/usecases/list-workflows/list-workflow.usecase.ts:8-34`, `libs/application-generic/src/utils/notification-template-mapper.ts:66-98`). The repository builds Mongo filters for name/trigger search, tags, status, sorting, skip/limit, and populated relation fields (`libs/dal/src/repositories/notification-template/notification-template.repository.ts:344-399`). A senior reader should notice that workflows are still persisted as notification templates, which is historically important naming context (`libs/dal/src/repositories/notification-template/notification-template.schema.ts:110-260`).

## First-Pass Mental Model

Novu is a pnpm/Nx monorepo with apps under `apps/*`, shared libraries under `libs/*`, product packages under `packages/*`, and enterprise/playground entries included in the workspace globs (`pnpm-workspace.yaml:1-16`). The main user-facing dashboard is a Vite React app (`apps/dashboard/package.json:6-26`, `apps/dashboard/vite.config.ts:48-131`). The main backend is a NestJS API service (`apps/api/package.json:8-43`, `apps/api/nest-cli.json:1-35`). Persistence is primarily through DAL repositories and Mongoose schemas, shown clearly by the context entity/schema/repository set (`libs/dal/src/repositories/context/context.entity.ts:6-21`, `libs/dal/src/repositories/context/context.schema.ts:5-69`, `libs/dal/src/repositories/context/context.repository.ts:8-92`).

## Teaching Anchors Chosen

The contexts path is the primary anchor because it is small enough to understand in one sitting and still shows the important architecture: route constants (`apps/dashboard/src/utils/routes.ts:68-70`), a page shell (`apps/dashboard/src/pages/contexts.tsx:10-35`), a complex table component (`apps/dashboard/src/components/contexts/context-list.tsx:140-281`), a URL-state custom hook (`apps/dashboard/src/components/contexts/hooks/use-contexts-url-state.ts:34-198`), a data-fetching hook (`apps/dashboard/src/hooks/use-fetch-contexts.ts:20-65`), HTTP helpers (`apps/dashboard/src/api/api.client.ts:27-112`), an API controller (`apps/api/src/app/contexts/contexts.controller.ts:39-205`), use cases (`apps/api/src/app/contexts/usecases/list-contexts/list-contexts.usecase.ts:11-90`), DTOs (`apps/api/src/app/contexts/dtos/create-context-request.dto.ts:6-50`), and Mongo schema/indexes (`libs/dal/src/repositories/context/context.schema.ts:5-69`).

The simple React component anchor is `ContextsPage`, because it shows page metadata, telemetry, layout, list composition, and drawer outlet without much noise (`apps/dashboard/src/pages/contexts.tsx:10-35`). The complex React component anchor is `ContextList`, because it coordinates URL state, data fetching, loading state, empty states, no-results state, sorting, pagination, and row rendering (`apps/dashboard/src/components/contexts/context-list.tsx:140-281`). The simple backend route anchor is `HealthController.healthCheck`, because it shows a Nest controller that composes health indicators and returns a Terminus health result (`apps/api/src/app/health/health.controller.ts:22-51`).

## Where A Junior Might Get Confused

A junior reader may expect `main.tsx` to only mount React, but this dashboard also defines the router there (`apps/dashboard/src/main.tsx:85-681`). They may also miss that `getV2('/contexts')` becomes `${baseUrl}/v2/contexts` because versioning is injected by the API client (`apps/dashboard/src/api/api.client.ts:64-65`, `apps/dashboard/src/api/api.client.ts:103-112`) and enabled by the backend bootstrap (`apps/api/src/bootstrap.ts:76-80`).

## Where A Mid-Level Engineer Should Slow Down

The cursor flow is worth careful reading. The UI stores cursor values in hook state and URL params (`apps/dashboard/src/components/contexts/hooks/use-contexts-url-state.ts:34-61`, `apps/dashboard/src/components/contexts/hooks/use-contexts-url-state.ts:87-163`). The backend resolves cursor IDs to context documents before calling repository pagination (`apps/api/src/app/contexts/usecases/list-contexts/list-contexts.usecase.ts:34-81`). This is easy to break with an innocent-looking sort or pagination change.

## Where A Senior Engineer Should Be Skeptical

Senior attention should go to auth boundaries, query behavior, and generated contracts. The frontend attaches bearer auth and `Novu-Environment-Id` headers in one HTTP wrapper (`apps/dashboard/src/api/api.client.ts:40-49`). The controller requires authentication and permissions (`apps/api/src/app/contexts/contexts.controller.ts:39-45`, `apps/api/src/app/contexts/contexts.controller.ts:122-123`). The search implementation escapes regex metacharacters before using `$regex` (`apps/api/src/app/contexts/usecases/list-contexts/list-contexts.usecase.ts:29-32`), and an e2e test asserts that regex metacharacters do not crash the endpoint (`apps/api/src/app/contexts/e2e/list-contexts.e2e.ts:142-156`).

## How To Use Checkpoints

For every checkpoint, first answer without looking. Then grade yourself by checking whether your answer names the relevant contract, owner file, and failure mode. Example: a strong answer to “where does contexts list data enter the dashboard?” names `ContextList`, `useFetchContexts`, `getContexts`, and the exact backend route chain (`apps/dashboard/src/components/contexts/context-list.tsx:156-168`, `apps/dashboard/src/hooks/use-fetch-contexts.ts:36-57`, `apps/dashboard/src/api/contexts.ts:10-74`, `apps/api/src/app/contexts/contexts.controller.ts:113-150`).
